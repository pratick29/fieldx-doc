Certificates & Credentials

Manage certificate installation and which apps may act as credential providers.

3
What it doesSets the device-wide default policy for which apps may act as credential providers.
OptionWhat it does
Default UnspecifiedNo default policy is enforced; individual app behavior applies.
Default DisallowedApps are disallowed from acting as credential providers by default.
Default Disallowed Except SystemOnly system apps may act as credential providers by default.
Available forAndroid Enterprise
Where to find itRestrictions / Certificates & Credentials / Default Credential Provider Policy

When should I use this? Use this to control the baseline trust level for credential-provider apps before layering on a specific allowlist.

What it doesAllows the listed app(s) to act as a credential provider. Applies to Android 14 and above.
What to enterEnter the package name(s) of the application(s) to allow as credential providers.
Available forAndroid Enterprise
Where to find itRestrictions / Certificates & Credentials / Allowed Credential Provider Apps

When should I use this? Use this to permit a specific, approved password manager or authentication app while keeping the default policy restrictive.

What it doesInstalls certificates onto the device.

Configured through its own settings window in the FieldX console rather than a simple Allow/Disallow toggle.

Available forFieldX EMM, Android Enterprise
Where to find itRestrictions / Certificates & Credentials / Install Certificates

When should I use this? Use this to deploy trusted root or client certificates needed for Wi-Fi, VPN, or app authentication.

This guide is based on the FieldX restriction material supplied for this documentation project.

Restriction names, descriptions, availability, and explicitly defined options are derived from the supplied FieldX source.

For standard FieldX controls, technical input types are translated into user-facing choices such as Allow/Disallow or On/Off.

Where the source does not specify a platform, option, or behavior, the guide does not invent a product-specific claim — it says so explicitly instead.

Compared to the prior edition, this revision merges option values that had been split out as standalone restrictions (e.g. Lock Screen Timeout’s "10/20/30 days/Never" choices, Non-Permitted App Action’s four choices, Reboot Schedule’s frequency choices) back into their parent restriction’s option table.

This revision also removes mismatched template text that did not match the restriction it appeared under, corrects a recurring grammar pattern ("can enabling" → "can enable"), fixes typos, and adds the Platform & Availability Glossary and the Master Restriction Summary appendix, which did not exist in the prior edition.
