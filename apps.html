Apps

Three ways to get apps onto devices — force-push APKs, curate a private store, or approve from Managed Google Play — then track rollout to every unit.

Push AppsCustom StoreManaged Play

PathApps → pick a tab: Push Apps, Custom App Store, Managed Google Play.
REFERENCE

Push Apps

Force-install APKs on managed devices, whether they are online now or come back later. Entries push the moment they are saved and enabled, and the detail sheet tracks rollout to every assigned unit.

Push Apps is the force-install channel: apps go to devices instead of waiting to be fetched. Entries push the moment they are saved and enabled; online units install at once, offline units catch up on reconnect.

What it doesPushes an app to devices immediately after saving its details. Devices must be online to receive it; offline units get it once they come back online.
ListSearch box + Add button; each row shows app Name, Package Name and a status dot; Rows-per-page pagination.
Where to find itApps → Push Apps

The detail sheet is one app’s mission control: who gets it, which build, whether it is on, where it downloads from — and the installed ring showing live rollout progress across the assignment.

ButtonsRefresh re-reads state, Start Rollout begins deployment, Edit opens the editor, Delete removes the app.
Enable flowNew entries start Disabled — search the entry, click Enable (top-right), and a green dot marks it live; pushing begins for the assigned groups.

Split packages exist because stores slim downloads per device configuration. FieldX sidesteps the store entirely, so it wants the raw APKs re-packed plainly — zips of zips and bundled folders will not install.

Split APKsGenerate the APKs, put them in one folder, and zip the folder contents — the ZIP must contain only APK files, no folders — then push the ZIP like any app.
XAPK / APKMRename to .zip, delete everything except the APK files, re-zip APKs only, and push.
Not supportedAAB format (Google Play) cannot be pushed.

Updates are new builds of the same listing, not new listings. The platform guards this with signature matching, so a wrong-key APK can never silently replace a production app.

1. Increment the Version Code and sign with v1+v2 using the SAME keys as before.
2. Upload to your hosting, copy the link.
3. Push Apps → search the listing → Edit → replace the link → details pre-populate.
Signatures must matchIf the signature hashes differ from the previous build, Save stays disabled.
4. Verify groups → Submit — devices update in a staggered rollout.

A listing is the portal’s record of an app, not the app on devices. Deleting tidies the catalog; the installed copies stay until a restriction or action removes them — hence disable-before-delete.

Push Apps → search → select the listing → Delete (top-right) → confirm.
Prefer DisableDisabling beats deleting for cleanup-safe pauses; delete only to tidy the section.
ImportantDeleting a listing does NOT uninstall the app from devices — add a “Force uninstall App” restriction for that.
GUIDE

Add & Edit dialogs

From a bare APK link to a rollout-ready entry: fetch details automatically, verify signatures and metadata, set permissions and install windows, then target groups and save.

Adding starts with a link, not an upload. The portal fetches the APK, reads its metadata, and pre-fills the form — the admin’s job shifts from typing details to verifying them.

1. Paste a Download Link → Fetch App Details.
RulesEnter a valid APK link that is directly downloadable. Google Drive and file-storage links are not supported — HTTPS only. See the Knowledge Base article for details.
SigningSign APKs with both v1 and v2 schemes, as Android recommends.
HostingUpload to your own web hosting (e.g. Amazon S3, GoDaddy). FieldX never hosts apps on the portal for security reasons; OneDrive, Google Drive and Dropbox links are not supported.

Editing is where deployment policy lives: what build, who gets it, when it may install, and whether it updates itself. Save re-targets the whole assignment in one move.

Auto-filled metadataPackage Name, Version, Version Code, File size, Min/Target SDK, Supported ABI — plus md5 / sha1 / sha256 Signatures for verification.
OptionsApp Name, Managed Config (+ Add/Update), Runtime Permissions (e.g. Prompt), Auto update from Google Play Store.
Install windowInstall anytime of the day, or around a time (~60 min) with a Time picker.
TargetingAll devices (in this Zone), or Push only to selected groups with an Assigned Groups picker. Finish with Save.

Custom App Store

Your own private store with only the apps users need — curated centrally, downloaded by choice. Ideal for fleets with no Play Store, with per-group visibility.

The private store flips distribution around: instead of pushing apps out, admins publish a shelf and users pull what they need. Same catalog mechanics underneath — groups decide who sees what.

What it isThe FieldX Store plugin — an internal, enterprise app store for devices with no Play Store. It is NOT preinstalled, so you choose exactly which devices or groups get it.
Put the Store on devicesDownloads → Plugin Apps → copy icon next to App Store → Push Apps → Add → paste the link → pre-populated details → pick Groups → Submit → open the entry → Enable (green dot = live) → auto-installs.
Fill the StoreHost APKs yourself (e.g. S3) → App Store page → Add → paste link to prefill → pick a Category (20 + Home, multi-select) → pick device groups → Save — entries appear for users to download.
Why GroupsGroup targeting makes the Store flexible: different apps for different devices, regions or zones.
Where to find itApps → Custom App Store (tutorial in the Knowledge Base)
REFERENCE

Managed Google Play

Approve public apps into your catalog through the embedded Play Store, then distribute them with FieldX targeting, managed configs and update modes.

Managed Play bridges the public store and fleet control: approve once from Google’s catalog, then distribute with FieldX targeting, configs and update modes. No sideloading, no APK hosting.

What it doesPick an app from the Google Play store and push it to devices. Click the Google Play icon to load the embedded store, then select apps into your App Catalog. List has Search, Play shortcut and refresh.
Detail extrasEverything in Push Apps, plus the Play Store listing URL, Managed Config JSON (e.g. VPN or server settings), Auto Update Mode (e.g. Default low-priority), and Grant Runtime Permissions (for v4.1+).
ButtonsEdit, Start Rollout, Delete.
Where to find itApps → Managed Google Play
