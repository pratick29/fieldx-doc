Firmware Management

Keep every device on the right software — staged firmware rollouts with rollback, delivered over CDN and tracked per device from download to installed.

REFERENCE

How an update flows

Stage it, let devices pull it, watch each unit move through the stages — and roll back the ones that fail.

3
Staged rollouts

Rollouts move in stages instead of all at once: prove the build on a small slice, then expand to the fleet. Each device reports its own stage — downloaded, installing, failed or rolled back — so a bad build is visible before it spreads.

The Updater agent

The Updater agent enforces firmware decisions on the device, pulling builds over CDN and installing them locally. Grab it from console Downloads alongside DeviceManager.apk and fieldx_settings.json.

Where to find itConsole Downloads
Rollback

Updates that fail don't strand devices: failed units roll back and report the rolled-back stage in the OTA report, ready for a fixed build. Check the failure stage first — downloads, installation and device-side blocks fail for different reasons.

REFERENCE

Track the rollout

The OTA report and one queue-clearing action cover the whole monitoring job.

2
The OTA report

The OTA report is the rollout dashboard: every device sits in exactly one stage — downloaded, installing, failed or rolled back. Filter by group or zone to see where an update is stuck, then export for the record.

Where to find itReports → OTA report → filter → Export
Stuck downloads

Interrupted transfers sit in the failed-downloads queue and retry dirty. Clearing the queue drops the stuck app and OTA downloads so they retry cleanly — the first fix to try before investigating further.

Where to find itDevices → select → Action → Clear Failed Downloads Queue
