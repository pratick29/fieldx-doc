Devices

Every enrolled device gets an inventory row, a details page with 100+ live parameters, nine console tabs, and one-click actions — this page maps them all.

Inventory table9 console tabsInstant actions8 min read

PathDevices → click a Device ID → Details, Locations, Installed Apps, App Limits, Device Shell, Screen View, Applied Restrictions, Logs, Action.
REFERENCE

Inventory & bulk actions

The fleet table lists every enrolled device with its identifiers and freshness, plus the gear menu behind it. Start here for daily checks, audits and bulk operations.

2
Device inventory table

The inventory is the master list of every device FieldX manages. Each row is one endpoint with its identifiers, owner, freshness and hardware. Admins start here for daily fleet checks, rollout audits, and locating a single unit by IMEI or serial.

What it doesLists every enrolled device with checkbox selection and columns for Device ID, IMEI Number, Serial Number, Device User, Alias, Last Seen Time, Model and Manufacturer.
ToolbarRefresh icon re-reads the list; Sync AE Devices pulls the latest Android Enterprise inventory.
Where to find itDevices (top-level console page)

Bulk actions apply one operation to many devices at once. Tick checkboxes, open the gear menu, and the command runs across the whole selection — moving zones, assigning groups, exporting records, or removing units.

What it doesThe gear icon applies one operation to every selected device.
Menu itemEffect
Change ZoneMoves devices to another zone with its policies
Assign GroupAttaches devices to a group for policy targeting
Assign User to deviceLinks a device to a user
Unassign UserReleases the device from its user
Export CSVDownloads the selected inventory rows
Bulk enroll DevicesStarts enrollment for a batch of units
Delete DevicesRemoves units from management
Archive DevicesArchives units out of the active lists

Details tab

One device, 100+ live parameters grouped by area — identity, system, battery, network and agent state. The diagnostic home for any misbehaving unit.

3

Identity fields never change for a device: its ID, IMEI, serial, model and OS version. Status fields change constantly: activation state, last-seen time, registration date and compliance posture. Together they answer two questions — which device is this, and is it healthy?

System & battery

System parameters show live resource pressure: CPU load, memory and storage fill, battery charge and temperature. Power and screen fields reveal how the device is actually used day to day. Check here first when a single device misbehaves.

SystemCPU load and frequency, memory and storage usage with percentages, external storage, brightness.
BatteryCharge remaining, charger plugged-in time, voltage, health status, battery and CPU temperature.
Power & screenPower-on time, power-save / idle / standby modes, resolution, size, orientation, ringer mode.
HardwareRadio, bootloader and build numbers, build type, device fingerprint, supported ABI, default apps (Home, keyboard, SMS, dialer), locale and time zone.
Network & EMM

Network fields show how the device reaches the world: Wi-Fi network and address, cellular SIMs and roaming, Bluetooth peers, VPN state and location mode. The EMM fields describe the management agent itself — its version, installation type and resource use.

Wi-FiConnected SSID, IP and MAC address, total Wi-Fi data usage.
MobileDual-SIM IMEIs, carrier, roaming status, mobile data usage per slot.
MoreBluetooth MAC and connected devices, VPN service and active state, location mode and last update, connectivity log.
EMM agentManager version, installation type (e.g. AE), app memory used/available, app UID.

Installed Apps & App Limits

See exactly what software lives on the device and cap how long it may run. Installed Apps is the truth; App Limits is the control.

2
Installed Apps

The installed-apps table is the software truth for one device: every package with its usage, data consumption, installed versus expected version, and whether it is a system app. Send App Action pushes commands to the selected apps.

What it doesPer-app table with Send App Action dropdown, Filter dropdown and Search.
ColumnsApp Name, Package, App usage, Data usage, Installed vs Expected Version, System App, State.
Where to find itDevices → select → Installed Apps
App Limits

App limits cap how long an app may run each day. Set a day, an app and a time budget; the platform enforces it and lists the active limits below. Built for shared, classroom and kids devices.

What it doesCaps daily usage per app — pick Day, App Name, Hour, Minutes, then Submit. Existing limits list below as Day / App Usage.
Where to find itDevices → select → App Limits

Monitor

Observe-only views: location trails, logs and the effective policy set.

3

Location trails replay where a device has been between two dates. Trails render on map or satellite views with a GPS point list beside them — exportable for records and SLA proof.

What it doesPlots GPS history between a Start and End date on a Map/Satellite view with a GPS Locations side panel.
Pick Start Date → End Date → Submit.
Toggle Plot All on Map; Export CSV for records; page with Rows selector.
Where to find itDevices → select → Locations
Device logs

Logs are the timestamped diary of device and agent events. Filter by type, search the text, refresh for the latest entries — the first stop for “what happened at 2am?” questions.

What it doesTime-stamped log messages with Search, Type filter (e.g. All Logs) and refresh.
Where to find itDevices → select → Logs
Applied Restrictions

Applied restrictions show the effective policy set on this exact unit: type, value and source policy name. When a device behaves unexpectedly, this table names the responsible rule.

What it doesSearchable table of effective restrictions: Restriction Type, Value, Restriction Name. Use it to confirm a policy reached the unit.
Where to find itDevices → select → Applied Restrictions

Remote actions

Do things to the device: shell, live screen and instant commands.

4

The shell is a remote terminal into the device for deep diagnosis — battery dumps, package lists, power whitelists — with no site visit. Commands run with the agent’s privileges, so treat access as sensitive.

What it doesRemote command-line into the device for diagnostics — no site visit.
dumpsys battery | grep level
pm list packages | grep fieldx
Where to find itDevices → select → Device Shell
Screen View

Screen view streams the live device screen and forwards taps, swipes and typing as if you held the unit. Unattended access skips on-device acceptance — the feature that makes kiosk and headless fleets supportable.

What it doesWatch and control the live screen — tap, swipe and type as if holding the device, with unattended access for kiosks.
Where to find itDevices → select → Screen View

Actions are immediate commands executed over the persistent channel — there is no polling delay. Pending marks commands not yet executed. The list spans information, messaging, power, security and maintenance.

What it doesPick an action on the left and run it on this device. The Pending badge marks actions not yet executed.
